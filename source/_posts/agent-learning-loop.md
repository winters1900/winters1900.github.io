这是博客重启后的第一篇笔记。我先不急着罗列框架，而是尝试回答一个更基础的问题：Agent 到底比一次普通的模型调用多了什么？

## 当前理解

我暂时把 Agent 理解为一个能够围绕目标反复运行的系统。模型负责判断下一步，工具负责影响外部世界，上下文保存当前任务状态，反馈则告诉系统刚才的行动是否有效。

一个最小工作循环可以写成：

1. 接收目标和当前上下文。
2. 判断下一步需要思考、调用工具，还是直接回答。
3. 执行动作并读取结果。
4. 更新上下文，检查目标是否已经完成。
5. 如果尚未完成，进入下一轮。

因此，Agent 不只是一个更长的提示词。它更像由模型驱动的控制循环。

## 四个核心部分

### 模型

模型负责理解目标、拆解问题和选择动作。模型能力决定了系统的推理上限，但模型本身并不能保证任务一定完成。

### 工具

工具把“生成文本”扩展成“执行动作”。搜索资料、读取文件、运行代码或调用接口，都属于工具使用。工具描述是否清晰、返回结果是否稳定，会直接影响 Agent 的判断。

### 上下文

上下文包含目标、约束、历史动作和工具结果。上下文太少会丢失关键信息，太多则可能让有效信号被噪声淹没，所以后续需要继续学习上下文压缩和记忆设计。

### 反馈

Agent 需要根据工具结果、测试结果或环境状态判断动作是否成功。没有反馈，系统只能“觉得自己完成了”；有了可验证的反馈，系统才有机会真正闭环。

## 接下来准备验证

下一步我想实现一个很小的 Agent，让它完成“读取一个代码仓库并生成结构说明”的任务。实验时重点观察三个问题：

- 它如何决定读取哪些文件。
- 工具返回异常时，它会不会调整计划。
- 什么样的完成条件才能避免过早停止。

这篇笔记只是第一版认识。后续会随着实验持续修正。
